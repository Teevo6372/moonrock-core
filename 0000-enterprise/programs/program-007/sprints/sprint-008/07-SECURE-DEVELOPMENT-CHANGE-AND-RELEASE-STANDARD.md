# Secure Development, Change, and Release Standard

Applications, infrastructure, configurations, automations, and integrations must incorporate security and privacy requirements from design through retirement.

## Requirements
- define trust boundaries, data flows, threats, and abuse cases;
- protect source, dependencies, build and deployment authority;
- prohibit secrets in code and artifacts;
- review material changes and separate approval from implementation where practical;
- test authentication, authorization, input handling, error behavior, logging, rollback, and recovery;
- track components, licenses, and known vulnerabilities;
- validate production release and observe post-release behavior.

Emergency changes require limited scope, evidence, approval under incident authority, and retrospective review.

Generated code and AI-assisted changes require the same review and testing as human-authored work.
