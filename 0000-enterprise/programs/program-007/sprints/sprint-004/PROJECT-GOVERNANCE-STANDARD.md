# Project Governance Standard

## Purpose
Define authority, accountability, project records, approval gates, and escalation requirements for every MEDS engagement.

## Project Record
Each project must identify:
- Enterprise client ID and engagement ID
- Project title, purpose, expected outcomes, and approved scope
- Executive, relationship, project, delivery, division, and client owners
- Agreement, proposal, Flight Plan, and decision-record references
- Budget, schedule, milestones, dependencies, risks, acceptance criteria, and support path
- Current lifecycle stage, health status, and next gate

## Authority
The Project Owner coordinates delivery but may not exceed approved scope, pricing, budget, data access, production authority, or contract terms. Executive approval is required for material commercial, legal, financial, security, asset, staffing, or reputational decisions.

## Governance Cadence
Projects must maintain an appropriate operating cadence covering status, schedule, scope, cost, quality, risks, decisions, client actions, and upcoming approvals. Material changes require an updated project record.

## Gates
No project advances solely because work has started. Each gate requires evidence that entry and exit criteria are satisfied, open exceptions are documented, and the authorized decision maker approves progression.

## Health Status
Use Green, Amber, Red, or Paused. Status must reflect evidence and include cause, impact, owner, response, and next review date.

## Escalation
Escalate when authority is unclear, client commitments conflict, critical dependencies fail, safety or security concerns arise, acceptance is disputed, budget or schedule tolerance is exceeded, or protected actions are requested.

## Boundaries
A project record, dashboard, or Nova output does not amend an agreement or authorize production changes.
