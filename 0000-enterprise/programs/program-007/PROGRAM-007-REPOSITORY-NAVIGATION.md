# Program 007 Repository Navigation

`0000-enterprise/programs/program-007/`

Sprint-specific standards are maintained under:

`0000-enterprise/programs/program-007/sprints/sprint-###/`

Current subsystem baselines:

- Sprint 006 — MEIS intelligence, analytics, and reporting

## Consumption Path
1. Start with `PROGRAM-007-EXECUTIVE-INDEX.md`.
2. Review the architecture map and glossary.
3. Identify applicable sprint domains using the dependency matrix.
4. Read the sprint README and charter.
5. Apply all relevant standards, matrices, and approval boundaries.
6. Record implementation-specific decisions outside MBOS while linking back to the governing standard.

## Document Classes
- **Index:** navigation and orientation; does not replace standards.
- **Charter:** sprint mission, scope, authority, exclusions, and completion criteria.
- **Standard:** mandatory reusable governance requirements.
- **Policy:** executive rules and boundaries.
- **Framework or model:** structured evaluation or maturity guidance.
- **Matrix:** roles, authorities, dependencies, or decision classifications.
- **Playbook:** governed execution guidance subordinate to controlling standards.

## Repository Boundaries
The repository may contain approved specifications, templates, diagrams, decision models, and governance records. It must not become the system of record for credentials, payment data, bank data, private client operations, regulated personal data, or unapproved legal and tax determinations.

## Implementation Referencing
Implementations should identify:
- governing document and version;
- applicable approval gate;
- accountable human owner;
- evidence retained;
- exception or deviation record;
- review date.

## AI Retrieval Guidance
AI systems should retrieve the narrowest applicable governing standards, check dependencies, state uncertainty, and escalate conflicts. AI summaries are convenience layers and are not authoritative when they differ from merged repository content.
