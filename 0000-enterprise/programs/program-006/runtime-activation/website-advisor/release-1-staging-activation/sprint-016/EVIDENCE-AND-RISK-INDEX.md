# Release 1 Evidence and Risk Index

## Evidence index

| Area | Required source | Acceptance condition |
|---|---|---|
| Repository preparation | Sprint 013 implementation record and deployment runbook | Staging manifest, schema, and rollback instructions retained |
| Automated validation | Sprint 014 JSON evidence | Health, readiness, provider isolation, and external-write gates pass |
| Private activation | Sprint 015 activation record | Revision, migration, rollback, provider mode, and operator decision recorded |
| Closeout | Sprint 016 closeout JSON | Evidence present, handoff complete, zero unresolved critical risks |

## Unresolved-risk register

Each unresolved item must include:

- unique risk ID;
- severity: low, medium, high, or critical;
- owner;
- mitigation or acceptance rationale;
- target resolution date;
- current status;
- evidence reference.

Release 1 staging closeout is blocked by any unresolved **critical** risk. High and lower risks may remain only when owned, documented, and explicitly accepted for continued private staging.

## Known operational limitations

- Repository records do not prove that Railway or PostgreSQL infrastructure was actually provisioned.
- Actual deployment and database evidence must be generated by the authorized infrastructure operator.
- Mock or disabled provider mode is required throughout this staging program.
- GHL and other external writes remain disabled.
- No public website or DNS activation is included.

## Audit retention

Retain sanitized evidence records with the corresponding deployment revision. Never commit secrets, tokens, raw connection strings, customer content, or production credentials.
